# Navigation evidence in RViz

The controller drives toward commanded target poses using laser-localized
feedback. It does not compute a Nav2 global plan. Report figures should be titled
**Commanded targets vs. laser-localized executed trajectory**, not Nav2 planned
path vs. ground truth.

Build and start the simulation as described in the root README. Before launching
the solution, open another container terminal and run:

```bash
cd /opt/erc_ws
source install/setup.bash
rviz2 -d /opt/erc_ws/install/erc_solution/share/erc_solution/config/erc_solution.rviz --ros-args -p use_sim_time:=true
```

Start the solution normally. The view appears after the shelf observation has
resolved the arena heading and laser localization has updated. It shows:

- Cyan: measured laser-localized base trajectory (`/erc/navigation/executed`).
- Pink arrows: commanded target positions and headings (`/erc/navigation/targets`).
- Grey rectangle: the static outer-wall model used by the localizer.
- Orange points: laser returns transformed by that same estimated pose.

The wall/scan overlay illustrates localization consistency, not an independent
ground-truth accuracy measurement. Targets are published when commanded, not
predicted in advance. Path samples are at most 5 Hz; up to 4000 samples and 100
targets are retained per mission. Visualization outputs do not feed navigation.

Capture an actual RViz screenshot near the shelf arrival and another on return
to the bin, with the display legend visible. Keep these with the report's source
assets. Do not use synthetic test output as trial evidence. Keep RViz open during
the trial: after the mission process exits, late subscribers cannot retrieve its
transient-local history. No screenshots have been generated by this change.

Required live column/book evidence remains separate in repository-root
`erc_images/`; the RViz figures do not replace those annotated camera images.
